# Telegram 转发机器人

独立项目，不依赖 Baserow / Google Sheets。

## 当前功能

- ➕ 添加转发任务：先设置源，再设置目标
- 🚫 自动阻止源和目标相同
- ▶️ 开始历史同步 / ⏸ 暂停历史同步
- 🔄 实时转发：按任务独立开启/关闭
- 👥 支持群、超级群、频道实时消息
- 🎛 实时消息按类型过滤：文本、图片、视频、文件、音频、语音、动图、贴纸、视频消息、其他
- 📊 任务进度：已处理、跳过、失败、百分比
- 💾 MySQL 保存任务、过滤设置和历史断点
- 🛡️ 防止同一任务重复转发同一个消息
- 🔁 重启后自动恢复数据库中仍处于运行状态的历史任务
- ⏱️ Telegram 返回 429 时自动等待 retry_after 后继续
- 🗑️ 删除任务时同时清理转发记录

## 历史同步说明

历史同步当前使用 Telegram Bot API 的 copyMessage，因此需要手动指定：

```text
任务编号 起始消息ID 结束消息ID
例如：
1 100 5000
```

机器人会按每批 10 条处理，并保存断点。不存在的消息会自动跳过，权限或其他不可恢复错误会暂停任务，避免持续报错。历史同步目前使用 Bot API 的消息 ID 直接复制，因此过滤设置只应用于实时转发。

## 实时转发说明

频道使用 channel_post，群和超级群使用普通 message 更新。

如果源是群/超级群，机器人需要能够接收到群内消息；通常需要正确的管理员权限或关闭群隐私模式，否则 Telegram 可能不会把普通成员消息推送给机器人。

## 环境变量

```text
BOT_TOKEN=
ADMIN_ID=
MYSQL_HOST=
MYSQL_PORT=3306
MYSQL_DATABASE=
MYSQL_USER=
MYSQL_PASSWORD=
```

## 部署

```bash
npm install
npm start
```

机器人必须被正确加入源和目标频道/群，并拥有发送、复制消息所需权限。

本项目不绕过 Telegram 的权限或受保护内容限制，只处理机器人/账号有权访问和发送的内容。
